WAF Observatory
Metrik Dataset Uji Analisis Realtime Komparasi Statistik Dokumentasi

Dokumentasi Webapp WAF Observatory

Aplikasi ini digunakan untuk mengevaluasi kualitas ringkasan insiden keamanan berbasis LLM terhadap log serangan dari ModSecurity.

Webapp menyediakan tiga mode utama: evaluasi dataset terlabel (offline), analisis realtime log WAF (online), dan komparasi statistik antarmodel (Shapiro + uji inferensial), lengkap dengan metrik evaluasi, ekspor laporan PDF, dan sistem riwayat persisten.

1. Fungsi Utama Webapp
  1. Evaluasi Dataset Uji: memilih TxID dari dataset historis (atau upload file custom), menjalankan inferensi ringkasan LLM secara asinkron di background, lalu menghitung metrik kualitas terhadap golden summary. Hasil evaluasi otomatis disimpan ke CSV dan riwayat.
  2. Analisis Realtime: membaca transaksi terbaru dari audit log ModSecurity (data terakumulasi di database, tidak hilang saat reload), memilih event tertentu, kemudian menghasilkan ringkasan otomatis berbasis LLM secara asinkron. Mendukung Executive Summary dan auto-refresh tanpa menghilangkan seleksi checkbox.
  3. Audit & Pelaporan: menyimpan hasil analisis ke SQLite untuk jejak evaluasi, lalu mengekspor hasil terpilih ke PDF (termasuk executive summary).
  4. Komparasi Model: menampilkan hasil uji statistik inferensial (Shapiro-Wilk, Paired T-Test / Wilcoxon, Holm-Bonferroni, Effect Size) dengan Chart.js visualisasi, interpretasi otomatis, dan kategori effect size.

3. Sistem Proses Asinkron (Background Task)

Seluruh proses AI (evaluasi dataset, analisis realtime, executive summary) dijalankan di background thread agar UI tidak freeze dan user dapat berpindah halaman tanpa membatalkan proses.

Alur Kerja
  1. User klik tombol proses → backend mengembalikan task_id secara instan.
  2. Frontend menyimpan task_id ke localStorage dan mulai polling setiap 1.5 detik ke GET /api/tasks/{id}.
  3. Progress bar dinamis menampilkan persentase aktual (0%–100%) berdasarkan progress/total.
  4. User dapat pindah halaman dan kembali → frontend mendeteksi task_id di localStorage dan melanjutkan polling otomatis.
  5. Saat task selesai, hasil ditampilkan dan task_id dihapus dari localStorage.

4. Dataset dan Sumber Data
  • Raw attack log: file audit ModSecurity berisi event transaksi serangan HTTP.
  • Golden summary: ringkasan referensi untuk TxID yang sudah dinormalisasi dan dipasangkan dengan log.
  • Join key: TxID digunakan untuk menyatukan raw log dan golden summary.
  • Output evaluasi: generated summary + skor metrik + latency per transaksi, otomatis disimpan ke CSV.
Upload Custom Dataset

Halaman Evaluasi Dataset mendukung upload file log (.log/.txt) dan golden summary (.csv) melalui tombol browse. Sistem akan menampilkan jumlah TxID yang berhasil di-join serta TxID yang tidak ditemukan di golden CSV. File yang diupload disimpan di direktori reports/uploads/.

5. Metrik Evaluasi (Penjelasan Lengkap)
ROUGE-1 F1

Mengukur overlap unigram antara ringkasan model dan golden summary. Cocok untuk mengukur kesamaan informasi tingkat kata. Semakin tinggi, semakin banyak konten inti yang selaras.

ROUGE-2 F1

Mengukur overlap bigram (frasa 2 kata). Lebih ketat dari ROUGE-1 karena menilai urutan lokal kata. Nilai tinggi menandakan kesesuaian struktur kalimat dan konteks lebih baik.

ROUGE-L F1

Menggunakan Longest Common Subsequence (LCS), menilai kesamaan urutan token tanpa harus bersebelahan langsung. Bagus untuk menilai alur naratif ringkasan.

METEOR

Menggabungkan precision dan recall token serta penalti fragmentasi. Dalam implementasi ini, METEOR dikombinasikan dengan resource WordNet/OMW saat tersedia agar lebih toleran terhadap variasi leksikal.

BERTScore F1

Metrik semantic similarity berbasis embedding transformer. Tidak hanya mencocokkan token literal, tetapi juga kedekatan makna antar kata/frasa. Model BERT (bert-base-multilingual-cased) di-preload saat server start agar tidak delay saat evaluasi pertama.

Latency (ms)

Waktu respons inferensi model dari request sampai output summary diterima. Metrik ini penting untuk menilai feasibility penggunaan realtime.

Interpretasi cepat: ROUGE/METEOR mengevaluasi kesesuaian tekstual, BERTScore mengevaluasi kesesuaian semantik, dan latency mengevaluasi efisiensi operasional.
6. Uji Statistik Inferensial
Alur Pengujian
  1. Shapiro-Wilk: menguji normalitas distribusi selisih per metrik. Metrik normal diuji dengan Paired T-Test, non-normal dengan Wilcoxon Signed-Rank.
  2. Uji Beda: Paired T-Test (Cohen’s dz) untuk data normal, Wilcoxon (Rank-Biserial Approximation) untuk data non-normal.
  3. Holm-Bonferroni: koreksi p-value untuk menghindari Type I Error pada pengujian majemuk.
  4. Effect Size: mengukur signifikansi praktis (bukan hanya statistik).

Visualisasi

  • Effect Size per Metrik: batang biru untuk nilai positif, oranye untuk negatif.

8. LLM dan Model yang Digunakan

Aplikasi ini menggunakan endpoint LM Studio lokal (OpenAI-compatible API) dengan model aktif:

  • google/gemma-3-4b
  • qwen/qwen3-4b-2507

Model dipilih di UI sebelum inferensi. Prompt yang digunakan bersifat domain-specific untuk incident summarization dari raw log ModSecurity, dengan instruksi Bahasa Indonesia formal.

BERTScore model (bert-base-multilingual-cased) di-preload saat server start di background thread agar evaluasi pertama tidak delay.

9. Penjelasan WAF (Web Application Firewall)
Konsep WAF

WAF bertugas memeriksa HTTP traffic masuk/keluar untuk mendeteksi dan memblokir pola serangan seperti SQLi, XSS, RCE, path traversal, dan anomali protokol.

Implementasi di Aplikasi Ini
  • Nginx sebagai reverse proxy.
  • ModSecurity sebagai inspection engine.
  • OWASP CRS sebagai rule-set standar industri.
  • Audit log ModSecurity menjadi sumber data analisis LLM.
  • Data log terakumulasi di database (tabel raw_logs) sehingga tidak hilang saat reload.
Manfaat Integrasi WAF + LLM

WAF memberikan deteksi rule-based yang presisi, sedangkan LLM membantu menerjemahkan event teknis menjadi ringkasan manusiawi untuk SOC analyst, pelaporan, dan triage cepat.

14. Alur Kerja Aplikasi
  1. User memilih model LLM.
  2. User memilih transaksi (TxID) dari dataset atau log realtime (atau upload file custom).
  3. Backend membentuk prompt dari raw log dan mengirim task ke background thread.
  4. Frontend polling progress dan menampilkan progress bar dinamis.
  5. Backend memanggil LM Studio untuk generate summary per transaksi.
  6. Jika ada golden summary, backend menghitung ROUGE, METEOR, BERTScore, dan latency.
  7. Hasil disimpan ke SQLite dan otomatis masuk riwayat. CSV juga di-generate untuk evaluasi dataset.
  8. User meninjau hasil melalui tabel + detail modal + chart. Dapat export PDF kapan saja.
15. Deployment Guide (Windows + WSL)
Prerequisite
  • Windows dengan WSL2 (Ubuntu).
  • LM Studio aktif di host dengan model sudah diload.
  • Akses sudo di WSL untuk setup Nginx/ModSecurity.
Langkah Ringkas
  1. Aktifkan backend virtual environment dan install dependency.
  2. Jalankan script setup WSL untuk Nginx + ModSecurity + service backend.
  3. Pastikan service aktif: nginx dan waf-observatory-backend.
  4. Akses aplikasi melalui http://localhost/.

16. Troubleshooting
  • 502 Bad Gateway: backend sedang warm-up model BERT atau service belum bind port 5000. Tunggu hingga log "BERT model siap!" muncul.
  • Model tidak muncul: pastikan model di LM Studio sedang loaded dan endpoint API aktif.
  • BERTScore kosong (N/A): pastikan package bert-score + torch sudah terinstall di venv backend.
  • Analisis lambat: normal untuk batch besar. Gunakan progress bar untuk memantau. Kurangi batch size jika perlu.
  • Log realtime tidak terbaca: pastikan permission file audit log ModSecurity bisa dibaca service backend.
  • 403 Forbidden saat hapus riwayat: ModSecurity memblokir HTTP DELETE. Aplikasi sudah menggunakan POST sebagai alternatif.
  • Task hilang setelah pindah halaman: task berjalan di background. Saat kembali ke halaman yang sama, task otomatis di-resume dari localStorage.
  • Checkbox ter-reset saat auto-refresh: centangan disimpan berdasarkan TXID, bukan posisi baris. Pastikan versi terbaru aplikasi.

18. Batasan dan Rekomendasi
  • Evaluasi summary sangat bergantung kualitas golden reference dan konsistensi gaya bahasa.
  • Sebagian sinyal semantic bisa tidak tertangkap metrik lexical murni, karena itu BERTScore penting dipakai bersama ROUGE/METEOR.
  • Proses AI berjalan di background thread (cocok untuk penggunaan tunggal). Untuk skenario produksi multi-user, gunakan task queue seperti Celery.
  • Audit dan retensi log sebaiknya mengikuti kebijakan keamanan organisasi.
